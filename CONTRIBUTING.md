# Як додати щось на сайт

Усе додається через pull request (PR). Ставити щось на комп'ютер не обов'язково:

1. Відкрийте потрібну папку в репозиторії на github.com (наприклад, `src/content/journal/uk/`).
2. **Add file → Create new file**, назвіть файл, вставте шаблон нижче й заповніть.
3. Унизу натисніть **Propose changes**, потім **Create pull request**.
4. Зачекайте на перевірку (Check). Зелена галочка — усе добре. Червоний хрестик — відкрийте **Details**: там написано, яке поле виправити.
5. Наставник перегляне й зіллє PR. Через пару хвилин зміни будуть на сайті.

Фото бувають двох видів, і зберігаються вони по-різному (докладніше в розділі «Правила для фото» внизу):

- **Без людей** (робот, плата, схема, поле змагань): додаєте самі так само через PR, **Add file → Upload files** у папку `public/media/<розділ>/<назва-файлу-тексту>/`. У тексті шлях пишеться без `public`: `/media/projects/line-follower-2026/cover.jpg`.
- **Де є люди**, навіть зі спини чи тільки руки: у репозиторій **не завантажувати**. Надішліть фото наставнику, він викладе його в Cloudinary команди й дасть посилання вигляду `https://res.cloudinary.com/…/image/upload/v…/….jpg`. Це посилання вставляєте в `cover` або в текст як `![опис](посилання)`. Сайт сам стисне фото й прибере з нього службові дані.

Назви файлів — латиницею, малими літерами, через дефіс: `line-follower-2026.md`, `2026-11-15-robotour-kyiv.md`, `olena-k.md`.
Назва файлу стає адресою сторінки, тож після публікації її краще не міняти.

## 1. Проєкт (робот) — `src/content/projects/uk/`

```markdown
---
title: "Лінійний трекер «Ворон»"
summary: "Швидко їздить по чорній лінії, кермується PID-регулятором."   # необов'язково, до 200 символів
status: in-progress          # idea | in-progress | done | retired
started: 2026-09-15
finished:                    # дата; обов'язково для status: done
cover: /media/projects/line-follower-2026/cover.jpg
cover_alt: "Робот на чорній лінії, вид згори"
team: [olena-k, maksym-d]    # назви файлів із members/ без .md
hardware:
  controller: "ESP32-S3"
  sensors: ["QTR-8A", "VL53L0X"]
  actuators: ["2× N20 6V 300rpm", "драйвер TB6612FNG"]
  power: "Li-ion 2S, 7.4 V"
code: https://github.com/97ohmrobotics/line-follower
video:                       # посилання на YouTube, якщо є
tags: [line-follower, pid, esp32]
---

## Задача
Що робот має робити і на якому змаганні / навіщо. 2–3 речення.

## Як він працює
Механіка, електроніка, алгоритм. Схема або фото плати тут доречні.

## Що не вийшло
Чесно: що зламалося, що переробляли, чого навчилися.

## Що далі
Плани на наступну версію.
```

- Розділ **«Що не вийшло» обов'язковий** для всіх проєктів, крім ідей: без нього сайт не збереться. Саме він робить сайт інженерним.
- Якщо `summary` порожній, на картці буде перший абзац тексту.
- Номер P-01, P-02… сайт ставить сам за датою `started`.

## 2. Допис у журналі — `src/content/journal/uk/`

Один формат для змагань, нотаток розробки й новин.

```markdown
---
title: "Robotour Kyiv: 4-те місце і перегрітий драйвер"
date: 2026-11-15
type: competition            # competition | devlog | news
project: line-follower-2026  # необов'язково: назва файлу проєкту
result: "4 місце з 18"       # тільки для type: competition
cover: /media/journal/2026-11-15-robotour-kyiv/field.jpg
cover_alt: "Поле змагань, команда спиною до камери"
authors: [maksym-d]
tags: [robotour, змагання]
---

Короткий текст: що було, що спрацювало, що ні, що змінимо.
Пишемо від «ми», без пафосу.
```

**Анонс змагання:** допис `type: competition` з майбутньою датою і без `result`. Він з'явиться на головній як «Найближче змагання».
Після змагань допишіть `result` і звіт у той самий файл.

## Правила для фото (поки немає згоди батьків)

- **Без облич.** Тільки загальні плани, спини, руки на роботі, сам робот.
- Якщо обличчя випадково в кадрі — обрізати кадр або не публікувати.
- Без прізвищ, номерів класів на одязі, бейджів з іменами.
- **Фото з людьми — тільки через наставника, у Cloudinary.** Git пам'ятає все: файл, який хоч раз потрапив у PR, назавжди лишається в історії репозиторію, навіть якщо PR закрили. З Cloudinary фото можна видалити повністю.
- Обов'язково заповнювати `cover_alt`: опис для людей, які не бачать зображення. Без нього перевірка не пройде.
- Фото в репозиторії: довга сторона до 2000 px, JPEG або WebP. Фото з Cloudinary сайт зменшує сам.

Портрети з'являться пізніше й тільки для тих, чиї батьки дали письмову згоду.
