# Інструкції для AI-агентів (Claude, Codex та інших)

Сайт робототехнічної команди «97 Ом» ліцею №97, Дніпро: https://97ohmrobotics.github.io.
Ведуть його учні й наставники через pull request. Цей файл — головний для агентів;
`CLAUDE.md` лише посилається сюди. Дизайн і кольори описані в [THEME.md](THEME.md),
інструкція для людей — у [CONTRIBUTING.md](CONTRIBUTING.md).

## Стек і команди

- Astro 7 + Markdown (content collections зі схемами Zod), звичайний CSS, без Tailwind і без CMS.
- Markdown обробляє Sätteri (стандарт Astro 7). Плагіни підключаються через `markdown.processor`
  в `astro.config.mjs`, а не через `rehypePlugins`.
- Node.js 24 (`.nvmrc`).

```sh
npm ci
npm run dev      # http://localhost:4321, чернетки (draft: true) теж видно
npm run build    # astro check + збірка; те саме запускає перевірка Check на PR
```

Перед кожним PR запускайте `npm run build`: схема контенту ловить більшість помилок
(порожній `cover_alt`, неправильна роль, чуже посилання на фото).

## Як вносити зміни

1. Ніколи не пушити в `main`. Нова гілка → коміт → pull request.
2. Тіло PR — за шаблоном `.github/pull_request_template.md` (розділи «Що змінено» і «Перевірка»).
3. Перевірка **Check** має бути зеленою. Зливає PR людина-наставник; автор PR не схвалює свій PR сам.
4. Один PR — одна зміна (новина, учасник, правка дизайну). Так їх легше переглядати.
5. Повідомлення комітів — українською, коротко, що змінено: «Журнал: допис про Robotour Kyiv».

## Де що лежить

```
src/content/journal/uk/   ← журнал: новини, змагання, нотатки розробки
src/content/projects/uk/  ← роботи й проєкти
src/content/members/uk/   ← учасники й наставники
src/content/pages/uk/     ← тексти головної (hero) і сторінки «Приєднатися»
src/content.config.ts     ← схеми всіх полів; якщо сумніваєтесь, які поля є, дивіться тут
src/lib/site.ts           ← назви, навігація, підписи статусів і ролей
src/lib/image.ts          ← правила для посилань Cloudinary
public/media/             ← фото без людей
public/brand/             ← логотип і фавікон — не змінювати
```

Папка `uk/` — мова. Англійська версія з'явиться згодом у `en/`, структуру не ламати.

## Новина в журналі (найчастіше завдання)

Файл: `src/content/journal/uk/<РРРР-ММ-ДД>-<2-3-слова-латиницею>.md`,
наприклад `2026-11-15-robotour-kyiv.md`. Назва файлу стає адресою сторінки — після публікації не міняти.

```markdown
---
title: "Robotour Kyiv: 4-те місце і перегрітий драйвер"
date: 2026-11-15
type: news                   # news | competition | devlog
project: line-follower-2026  # необов'язково: назва файлу проєкту без .md
result: "4 місце з 18"       # тільки для type: competition
cover: https://res.cloudinary.com/lyceum97media/image/upload/v1792951743/cover.jpg
cover_alt: "Поле змагань, команда спиною до камери"
authors: [serhii]            # назви файлів із members/uk/ без .md
tags: [змагання]
---

Текст: що було, що спрацювало, що ні, що змінимо. Від «ми», без пафосу.
```

- Анонс змагання: `type: competition`, дата в майбутньому, без `result` — з'явиться на головній.
  Після змагань у той самий файл дописати `result` і звіт.
- `draft: true` — чернетка, на сайт не потрапляє.
- Наставники в `members/uk/`: `serhii` (Сергій), `maksym` (Максим).

Інші типи контенту (проєкт, учасник, сторінка «Приєднатися») — шаблони в CONTRIBUTING.md.
Важливе для проєктів: розділ `## Що не вийшло` обов'язковий для всіх, крім `status: idea`.

## Фото: де зберігати

| Що на фото | Де | Як вказати |
|---|---|---|
| Без людей: робот, плата, схема, поле | репозиторій, `public/media/<розділ>/<назва-файлу-тексту>/` | `cover: /media/journal/2026-11-15-robotour-kyiv/field.jpg` |
| **Є люди**, навіть спиною чи тільки руки | Cloudinary команди (cloud name `lyceum97media`), завантажує наставник | посилання **Copy URL** як є |

Чому так: git і навіть закриті PR зберігають файли назавжди, фото з дітьми звідти не видалити.
З Cloudinary — можна. **Ніколи не додавайте в репозиторій фото, де є люди.**

- Посилання Cloudinary вставляти без змін: `https://res.cloudinary.com/lyceum97media/image/upload/v…/….jpg`.
  Не дописувати перетворення (`w_800`, `c_fill` тощо): сайт сам підставляє розміри, WebP/AVIF і `srcset`.
  Посилання з будь-якого іншого сайту схема відхилить.
- Перед завантаженням у Cloudinary з фото треба стерти EXIF (GPS): squoosh.app, `exiftool -all=`.
  Сайт віддає фото без EXIF, але оригінал за посиланням без перетворень його зберігає.
- Папки в Cloudinary повторюють сайт: `home/`, `journal/<назва-файлу-допису>/`, `projects/<назва-файлу>/`, `team/`.
- Пропорції: обкладинка допису й проєкту 21:9 (обрізається по центру), фото першого екрана 4:3,
  картка проєкту 3:2. Фото в репозиторії — до 2000 px по довгій стороні.
- `cover_alt` / `hero_alt` обов'язкові й **описують зображення** для незрячих, а не підпис-гасло.
  Добре: «Робот на чорній лінії, вид згори». Погано: «Ми готові до нових викликів!»
- Згенероване ШІ зображення позначати: `cover_alt: "Ілюстрація: …"`. Не видавати його за фото команди.

## Приватність (учні неповнолітні)

- **Без облич** учнів, доки немає письмової згоди батьків: загальні плани, спини, руки, роботи.
- Учні — тільки ім'я й перша літера прізвища: «Олена К.». Без повних прізвищ, класів на одязі, бейджів.
- Не публікувати телефони, адреси, особисті акаунти учнів.

## Мова й назва

- Сайт українською. Тон спокійний, інженерний, від «ми», без пафосу й гучних обіцянок.
- Назва в тексті: **«97 Ом»** (укр.), **97 Ohm Robotics** (англ., коротко 97 Ohm). Знак Ω — тільки в логотипі.
- Адреса й хендли: `97ohmrobotics`.
- Перевіряйте змішані алфавіти: латинська «O» замість кириличної «О» в «97 Ом» ламає пошук.

## Зміни в коді й дизайні

- Перед правками вигляду прочитайте [THEME.md](THEME.md): кольори тільки через CSS-змінні,
  обидві теми (світла й темна), сітка «Синьки».
- Темна тема в `src/styles/global.css` записана двічі (ручний вибір і «авто») — міняєте одне, міняйте обидва.
- Коментарі в коді — українською, коротко, як у сусідніх файлах.
- Перевіряйте сторінку на ширині 390 px (телефон) і 1280 px.
- Не додавайте залежності без потреби; секрети й ключі API в репозиторій не комітити
  (cloud name Cloudinary — не секрет).
